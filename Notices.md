## 4. Implementer acceptance under CSL Section 2.1.3.3

No separate repository-route implementer acceptance is recorded in this release. That does not describe implementers using the distribution-based routes in Sections 2.1.3.1 or 2.1.3.2.

To use the repository route, the implementer's authorized representative must issue a pull request or commit to this file containing an explicit acceptance of CSL, the implementer's legal name, the authorized individual's name and system identifier, and the exact ACES specification version. Also record the actual date, Scope/release reference and the original pull request or commit reference.

A suitable affirmation is:

> The identified implementer accepts Community Specification License 1.0 for the identified ACES version, including the applicable reciprocal patent terms. I am authorized to make this acceptance on that implementer's behalf.

Membership or contributor acceptance does not replace this distinct route. For a distribution route, include the full CSL as specified in the license, not only a link.

## 5. Patent exclusion notices

No patent exclusion notice is recorded as of the framework's effective date. This is a statement about this register, not a declaration that no patents or possible claims exist.

An Exclusion Notice must be issued by a pull request or commit to this file and satisfy CSL Sections 3 and 9.7. Identify the notifying party and representative, specification, relevant contribution or approval event, actual notice date and the patent information required by the license:

- For issued patents and published applications, include the patent numbers or application titles and numbers, as applicable.
- For unpublished applications, provide either the filed application text or the specific specification portions whose implementation makes the excluded claim a Necessary Claim, as allowed by Section 9.7. Do not require confidential application text when the license allows the latter route.

Retain the original notice and its timestamp, affected provisions, corrections and any separately recorded assessment or resolution. Section 3.1 provides the contribution-based 45-day rule and its limitation for material already in the draft. Section 3.2 separately addresses pre-approval exclusions; it does not reopen claims eligible under Section 3.1. The full license controls.

Issuing the required notice is distinct from maintainer approval of its substance. Preserve unmerged and disputed notices; do not conceal them by refusing a merge. Governance approval rules cannot cancel a valid exclusion. Resolve affected requirements under `Governance.md` before Approved Specification designation.

Where repository access is restricted, contact the coordinator promptly for a submission path. The coordinator must facilitate a timely repository action by the entitled party or its authorized agent. Email alerts and access requests do not by themselves replace the CSL repository requirement. Keep a public copy of current notices and versioned release snapshots.
